# Changelog

Releases are tagged `v<version>`; each entry says what changed for an operator.

## 0.9.0

- **Post primitive.** `carl post dry-run | approve | now | schedule | clear-pending | status` publishes a post from a Markdown draft (front matter: `platform`, `account`, `text` or `thread`, optional `reply`). One adapter contract per platform (`src/post/types.ts`, registry in `src/post/registry.ts`); X is the first adapter, driven through an owned `overseer-browser` session with an explicit `--timeout`.
- **No double click.** A `pending_part` record is written (and must succeed) before every Post click. Any failure after the click is final and never retried; a rerun only looks for the pending part on the profile and refuses until the operator clears it with `carl post clear-pending`. Only failures before a click are retried by the scheduler.
- **Verification.** A live post counts only if its whole normalised text matches (emoji read from `<img alt>`), X created it no earlier than the approval, its id is newer than the profile's newest post before the click and than the previous part, and it is not already recorded. Recorded parent URLs must be `/<handle>/status/<id>` of the account, once each. The browser must be signed in to the configured account (checked before filling), the profile must be an https X URL, and the composer is re-read at click time.
- **Approval gate.** Posting, live or scheduled, refuses unless the draft carries `approved:` and an `approved_hash` that is an HMAC-SHA256 (key `CARL_HOME/post-approval.key`, 0600, denied to the sandbox) over platform, account, profile, text, thread and reply. `carl post approve` needs a terminal, shows what is live, passes the hash of what it displayed so a draft edited at the prompt is refused, and refuses to re-approve an edited live part. Control and bidi characters in a draft are refused. A live dry run of the exact text (`dry_run_hash`) is required unless the operator passes `--skip-dry-run`.
- **Agent boundary.** The `post_draft` tool drafts, dry-runs and gives an approved draft its first slot; it cannot approve, post at once, change a slot or choose `late`, and the `schedule` tool refuses to run or resume a post job. A post job refuses to fire before its slot unless the operator forces it. With `post.accounts` configured, the sandbox profile denies the OverSeer browser control directory (read, write, socket) and the approval key, and the guard refuses `overseer-browser` in the agent's shell. A `draftsDir` (or draft) inside a folder the agent can write is refused.
- **Durable scheduling.** A new `post` schedule job kind (one-time, in `schedules.json`) fires a draft at `scheduled_at`. A slot missed by more than `post.missedWindowMinutes` (default 180) is skipped and the delivered message says so (never when a click was started); `--late post` (operator only) posts it late. `schedules.json` writes are locked and merged: the CLI no longer rewrites running job state, and a job it removes is dropped by a running gateway.
- **Gateway PATH.** `post.accounts.*.session.command` is resolved from the operator's PATH at start and pinned like Carl's other programs, so scheduled posts can start the browser CLI from the gateway. Child processes get a scrubbed environment.
- **Config.** `post` in `carl.json`: `draftsDir`, `missedWindowMinutes`, `retex`, and `accounts` (the only place accounts are defined).
- Draft writes are compare-and-set against the file as read (`retex set --if-hash` when retex is installed and nothing is cleared, otherwise an atomic write); a failing retex is an error. A fully live draft that was never marked Posted is just marked Posted. `media:` and a thread's `reply` are refused; inline `[..]` lists apply only to `thread`, `thread_urls`, `media`; X length counts CJK and emoji as 2.
- Docs: `docs/POSTING.md` and a README section.
